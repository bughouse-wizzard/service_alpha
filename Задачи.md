## Шаг 7 — Конвейер исполнения “тесты → реализация → PR → merge → валидаторы” (последовательно)

> В вашем ТЗ: сначала воркер пишет тесты под маленькую задачу, потом другой воркер делает код вместе с тестами; затем merge worker; затем code review validator; затем build/tests validator; если замечания — обратно в планировщик.

### Группа 7.1 (одна задача) — Оркестрация парных воркеров: Test-Worker → Dev-Worker

* **Цель:** на уровне каждого WorkItem:

  1. создать conversation “TEST_WRITER” (генерит/обновляет тесты),
  2. передать результат/патч в conversation “IMPLEMENTER”.
* **Acceptance:** в БД фиксируются оба воркера/сессии, артефакты, ссылки на ветки.
* **Файлы:** `main.py`, `client.py`, `db.py` .

### Группа 7.2 (параллельно) — “Task templates” под роли (junior-sized)

* **Задача 7.2a:** шаблон промпта для TEST_WRITER (ограничения/формат/команды)
* **Задача 7.2b:** шаблон промпта для IMPLEMENTER (принимает тесты, делает минимальный код)
* **Задача 7.2c:** шаблон промпта для FIXER (исправление замечаний)
* **Acceptance:** шаблоны в коде + документация; соответствуют паттернам промптинга .

### Группа 7.3 (одна задача) — Merge Worker (автоматический мерж веток)

* **Цель:** после готовности задач создаётся отдельный воркер, который:

  * синхронизирует ветки,
  * решает конфликты,
  * делает merge в целевую ветку (через VCS Adapter).
* **Acceptance:** мерж либо успешен, либо создаёт список конфликтов как новые WorkItems.
* **Файлы:** `main.py`, `vcs/*.py`, `db.py`.

### Группа 7.4 (одна задача) — Validator: Code Review against TЗ + частные задачи

* **Цель:** отдельный воркер-ревьюер: проверяет соответствие плану/ТЗ, стиль/паттерны .
* **Acceptance:** выдаёт структурированный verdict (APPROVED/CHANGES + список замечаний в формате “новые задачи”).
* **Файлы:** `planner.py` (анализ результата), `main.py`.

### Группа 7.5 (одна задача) — Validator: Build + Tests

* **Цель:** отдельный воркер запускает сборку/тесты (локально/CI), сохраняет логи.
* **Acceptance:** при fail — авто-генерация задач на исправление; при pass — перевод цикла в DONE.
* **Файлы:** `main.py`, `db.py`, dashboard.

### Группа 7.6 (одна задача) — Feedback Loop: замечания → планировщик → новые мелкие задачи

* **Цель:** автоматический “replan” с учётом history.
* **Acceptance:** создаётся новый DevelopmentCycle (итерация) с корректировками; UI показывает все циклы.
* **Файлы:** `planner.py` (feedback_history уже предусмотрен параметром) , `db.py`, dashboard.
